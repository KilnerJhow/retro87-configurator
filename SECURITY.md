# Security

## Supported versions

| Version | Support |
|---|---|
| `0.0.x` | yes (current line) |
| others | no |

## Reporting

**Do not open a public issue** for flaws involving device writes, configuration corruption,
bypassing the write lock, or exposing device data.

Use GitHub's **Private Vulnerability Reporting** (*Security* tab → *Report a vulnerability*).
Include:

- version (`Retro87 --version`) and operating system;
- VID/PID and family (JP/Xbox);
- whether the keyboard was connected by cable or dongle;
- the report generated by `Retro87 --report` (it is read-only);
- steps to reproduce and the expected behavior.

## Scope

Relevant flaws:

- writing without the explicit lock;
- writing without a backup or readback;
- firmware commands (the app must have no download/flash path);
- selecting the wrong HID collection, potentially sending a write frame to the wrong interface;
- leaking paths, serial numbers, or configuration contents in logs/reports;
- a vulnerable dependency with a reachable code path.

Out of scope:

- keyboard firmware bugs;
- official app behavior;
- lack of support for a PID not listed in `KnownDevices`;
- denying access without the udev rule installed (a documented requirement).

## Principles

- **Reading is unrestricted; writing is deliberate.**
- **Never write firmware.**
- **Backup first, readback afterward.**
- **The report is sanitized:** it does not include the raw 1532 configuration bytes.
- **Minimal dependencies:** Avalonia, HidSharp, CommunityToolkit.Mvvm.

## Disclosure

The maintainer acknowledges receipt, investigates, and agrees on a disclosure timeline. Since
the project interacts with hardware, a fix may require a reversible probe and a device session.
